The plugin has two tabs at the top, with the active [profile](../profiles/) next to them, which both use. **Export** holds the settings most exports need, the servers and **Download JSON**. **Import** writes tokens into the variables of the file, from a [server](../push-to-server/#pull-from-server) or a [JSON file](../../getting-started/export-and-import/#import-json--variables). The plugin opens on Export, or on Import when the file has no variables yet. Everything else is under [Advanced settings](https://github.com/tokens-bruecke/figma-plugin/blob/main/../advanced-settings/).

## Color mode

Allows you to choose the color mode for the generated JSON. Default value is `HEX`. The plugin supports the following color modes:

- `HEX` — HEX color format. Could be converted into `HEXA` if the color has an alpha channel.
- `RGBA CSS` — RGBA color format in CSS syntax, e.g. `rgba(0, 0, 0, 0.5)`. When alpha is `1`, the output is `rgb(r, g, b)` (no alpha channel).
- `RGBA Object` — RGBA color format in object syntax, e.g. `{ r: 0, g: 0, b: 0, a: 0.5 }`.
- `sRGB DTCG` — sRGB color format in object syntax matching the [DTCG specification](https://www.designtokens.org/tr/2025.10/color/#srgb)
- `HSLA CSS` — HSLA color format in CSS syntax, e.g. `hsla(0, 0%, 0%, 0.5)`.
- `HSLA Object` — HSLA color format in object syntax, e.g. `{ h: 0, s: 0, l: 0, a: 0.5 }`.
- `HSL DTCG` — HSL color format in object syntax matching the [DTCG specification](https://www.designtokens.org/tr/2025.10/color/#hsl)
- `OKLCH DTCG` — OKLCH color format in object syntax matching the [DTCG specification](https://www.designtokens.org/tr/2025.10/color/#oklch)

The DTCG color objects carry the opacity in `alpha` and a 6-digit `hex` fallback, as the specification requires. Older exports wrote an 8-digit `hex` for translucent colors; the import reads both.

## Include styles

Allows you to include styles into the generated JSON. Text, effect, grid and color styles each have their own toggle, and all of them are `off` by default. See more about styles support in the [Styles support](../../reference/styles/) section.

There is an option to rename each style's group and give it a custom name for better organization.

<Screenshot name="rename-styles" alt="Renaming the group of the typography styles" />

## Add styles to

Shown once at least one style type is included. Allows you to choose where to put styles in the generated JSON. By default, the selected value is `Keep separate`. In this case styles will be added into the root of the JSON and will be treated as collections. There is also an option to add styles into the corresponding collection. If that collection isn't in the export (for example in another file, or with [Omit collection names](../advanced-settings/#omit-collection-names)), the styles are kept separate.

## DTCG 2025.10 format

Is `on` by default. Aligns the output with the [DTCG 2025.10 specification](https://www.designtokens.org/tr/2025.10/format/):

- All token keys are prefixed with the `$` symbol (`$value`, `$type`, `$description`).
- Dimensions are exported as objects per [§8.2 Dimension](https://www.designtokens.org/tr/2025.10/format/#dimension) — `{ "value": 6, "unit": "px" }` instead of `"6px"`. This also applies to sub-values in shadows, typography, and grids.
- The root `$extensions["tokens-bruecke-meta"]` includes a `spec` field with the canonical spec URL, so downstream tools know which format to expect.
- A variable named like a group of other variables (`border/brand` next to `border/brand/subtle`) becomes the group's root token per DTCG 2025.10 §6.2: `border.brand.$root`. References to it point at `{….border.brand.$root}`. With the format off, the token and the group share one object, as before. The import reads both shapes.

```json
// Off — native Figma format
{
  "button": {
    "background": {
      "type": "color",
      "value": "#000000"
    },
    "height": {
      "type": "dimension",
      "value": "32px"
    }
  }
}

// On — DTCG 2025.10 format
{
  "button": {
    "background": {
      "$type": "color",
      "$value": "#000000"
    },
    "height": {
      "$type": "dimension",
      "$value": { "value": 32, "unit": "px" }
    }
  }
}
```

:::note
Values that have no valid DTCG representation stay as strings even with this setting on: percentage-based `lineHeight`/`letterSpacing` (e.g. `"150%"`) and `"auto"` line height. `blur` and `grid` style tokens are exported with non-spec `$type` values as documented in [Styles support](../../reference/styles/).
:::

## Download file name

<Screenshot name="download-settings-split" alt="Download settings with the file name field" />

The **…** button next to **Download JSON** opens **Download settings**. **File name** is empty by default, which keeps the name `design.tokens.json`. Set it so the file can be committed as it is, or so several exports can sit in one folder without the browser adding `(1)`, `(2)`.

- The extension is optional: `brand` and `brand.json` both download as `brand.json`.
- When the files are [split by collection or mode](../advanced-settings/#split-collections-into-separate-files), the archive takes the same name, e.g. `brand.zip`. The files inside keep their `{CollectionName}.tokens.json` names.
- Characters that aren't allowed in file names, such as `/` or `:`, are replaced with `-`.

The name is saved in the [profile](../profiles/) and shared with it. It only applies to downloads: a push writes to the `File name` of each server, and the CLI to `--output`.
