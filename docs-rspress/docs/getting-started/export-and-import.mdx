title: "Export and import"
description: "Export Figma variables as DTCG tokens, or import tokens back into Figma variables."
---

The plugin supports both **exporting** and **importing** design tokens:

## Export (Variables → JSON)

- Click **"Download JSON"** to export your Figma variables as a design tokens JSON file
- The exported file is compatible with the [DTCG 2025.10 specification](https://www.designtokens.org/tr/2025.10/format/)
- You can also push directly to supported services (JSONBin, GitHub, GitLab, etc.)
- The exported tokens can be converted into CSS, JS, and other platform formats using tools like [Terrazzo](https://terrazzo.app/docs/) or [Style Dictionary](https://amzn.github.io/style-dictionary/)

## Import (JSON → Variables)

- Open the **Import** tab and click **Import from JSON file** to import design tokens from a JSON file back into Figma. The import runs in Figma Design only, not in [Dev Mode](/plugin/dev-mode)
- With a server set up, the ↻ button of a server on the Import tab imports the tokens straight from it: from a GitHub or GitLab repository all files of a split export at once, or the JSON of a JSONBin bin or your own URL. See [Pull from server](/plugin/push-to-server#pull-from-server)
- The plugin will create variable collections, modes, and variables based on the JSON structure
- Supports both DTCG format (`$value`, `$type`) and standard format (`value`, `type`)
- Handles alias references between variables
- Creates new collections and variables as needed, or updates existing ones

A file without variables opens on the Import tab, so you can pull its tokens or choose a file right away. Once the import created variables, the plugin switches to Export. In [Dev Mode](/plugin/dev-mode) such a file shows "No variables found in the file" instead, because Dev Mode can't import.

**Import Features:**

- ✅ Creates variable collections from top-level objects
- ✅ Supports multiple modes (from `$extensions.mode` or `extensions.mode`)
- ✅ Handles all variable types (color, number, string, boolean, timing, easing)
- ✅ Resolves alias references between variables
- ✅ Supports these color formats: HEX, RGBA CSS, RGBA Object, DTCG color objects (`srgb-dtcg`, `hsl-dtcg`, `oklch-dtcg`, through their `hex` fallback) and [color aliases with opacity](/reference/aliases#color-aliases-with-opacity). HSLA CSS and HSLA Object can't be imported yet
- ✅ Imports variable descriptions and `scopes`. Empty `scopes` hide the variable from every picker. Invalid scopes are reported, and scopes are skipped on `duration` and `cubicBezier` tokens
- ✅ Imports the code syntax of each platform from [Figma metadata](/plugin/advanced-settings#include-figma-metadata) (`$extensions.figma.codeSyntax`). Platforms the token leaves out are cleared; without the metadata, a variable keeps its code syntax. Variable and collection IDs are ignored, since a new file gives its own
- ✅ Imports `duration` and `cubicBezier` tokens as Figma motion variables (see [Motion variables](/reference/types#motion-variables))
- ✅ Imports `fontFamily` and `fontWeight` tokens without `scopes` as new variables scoped to "Font family" and "Font weight", so they keep their type on the next export. Existing variables keep their scopes. A `fontFamily` list keeps only its first family, since a string variable holds one

**What to know before importing:**

- Tokens without their own `$type` take it from the closest group, as DTCG allows; an alias without a type takes the type of the token it references.
- Every top-level key becomes a collection. Files exported with [Omit collection names](/plugin/advanced-settings#omit-collection-names) don't map back to the original collections.
- A file of a [split-by-mode export](/plugin/advanced-settings#split-modes-into-separate-files) carries its mode in the meta, so its values go into that mode of the collection, which is added if it's missing. Import the files one by one, or [pull them from Git](/plugin/push-to-server#pull-from-server) all at once; the first one imported into a new collection becomes its default mode.
- An existing collection's first mode is renamed to the first mode in the tokens.
- Units are dropped from dimensions, since Figma number variables have no unit: `1rem` imports as `1`.
- Extended collections are imported as regular collections when they don't exist in the file yet. If the extended collection exists, its tokens update the variables it inherits: the values become overrides for its modes. New variables and modes can't be added to an extended collection, so those tokens are reported as errors.
- An existing variable keeps its type. A token of another type, for example a `dimension` token for a color variable, is skipped and listed in the import result.

:::warning
**Styles Export Limitation**: If you exported tokens with styles included (typography, grids, shadows, or blur), these cannot be imported back as Figma styles. Figma variables only have color, number, string and boolean types, plus timing and easing for motion. Solid color styles import as color variables. Typography, grid, shadow and blur tokens fall back to `STRING` variables, but their object values can't be written, so they are reported as errors in the import result.
:::
